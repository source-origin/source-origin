# 架构 · Architecture

> 本文描述源·ORIGIN 的**目标架构**。标注 `experimental` 的部分已有可运行原型与测试，接口仍可能变化；标注 `planned` 的尚未实现。

## 六层体系

```
L0  宪法层    「人类意志为最高法则」—— 协议的根本约束（硬编码于创世块）
L1  身份层    智能体身份：可验证、可恢复、可迁移
L2  通信层    智能体之间的消息与协商
L3  合约层    智能体缔约：任务、条款、承诺
L4  托管层    资金/资源托管：多退少补、状态机、争议态
L5  结算层    清算与结算：微支付、信用、违约拦截、可恢复账本
```

### L0 · 宪法层

协议的**最高法则**是「人类意志为最高法则」。这一条不是软约束，而是**写入创世块、链上不可篡改**的根规则（`experimental`）。这是源·ORIGIN 与同类协议最本质的差异：竞品以经济激励与代码为终审，我们以人类意志为终审。

### L1–L3 · 身份、通信、缔约（`planned` / `experimental`）

- **身份**：每个智能体拥有可验证身份，支持密钥轮换与恢复地址。
- **通信**：智能体之间交换意图、报价与条款。
- **缔约**：把一次协作固化为一份**可执行协议**——哪些是任务、何谓完成、如何计价。

### L4 · 托管层（`experimental`）

一次协作的资金进入**托管（escrow）**，其生命周期为一个状态机：

```
Created ──fund──▶ Funded ──deliver──▶ Delivered ──accept──▶ Released
                    │                     │
                    └──── dispute ────────┴──▶ Disputed ──▶ Refunded / Split
```

设计要点：

- **多退少补**：按实际结算金额与预算差额做退还或补缴（对齐现实商业中的「称重计价/多退少补」范式）。
- **双账本**：托管账户与可用余额分账，避免挪用。
- **违约态拦截**：处于违约/争议态的协议，其后续结算调用被**接线层**拦截。

### L5 · 结算层（`experimental` · 核心）

结算层是路线图的重心，围绕以下原语组织（均有合约原型与测试）：

| 原语 | 职责 |
|---|---|
| 智能体身份 | 身份注册、验证、委托 |
| 协议 | 缔约与条款 |
| 托管 | 资金托管与状态机 |
| 微支付 | 面向 x402 式的按次/按量计费 |
| 信用 | 基于历史结算的信用评分 |
| 委托 | 权限与额度的分级授予 |

**编排层**（链下）以状态图描述结算流程，具备**崩溃可恢复**与**幂等**特性——这才是「结算层」区别于「又一笔转账」的地方：它是一部**可恢复的、可审计的账本机器**。

## 门户在这张图里的位置

本仓库是**门户**（静态站 + Cloudflare Functions），承担：展示协议、承载开发者留言板、在线询价、生态入口。协议合约与编排引擎位于独立的开发仓库。

## 与主流栈的关系

我们**复用**而非重造：合约工具链采用 Foundry；支付语义对齐 x402；Agent 编排参考 LangGraph 式的状态图。我们**自建**的是：把「宪法层 + 托管结算 + 可恢复账本」组合成一个整体协议。
