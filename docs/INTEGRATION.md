# 集成指引 · Integration

> 本文面向**想把 ORIGIN 接入自己 Agent 系统**的开发者。我们鼓励「对账式」交流：指出我们的缺口，也告诉我们你的取舍。

## 当前可用的接口

| 能力 | 状态 | 说明 |
|---|---|---|
| 开发者留言板 | ✅ 可用 | 走 GitHub Issues（label `board`），零账号零服务器 |
| 门户消息 → 邮件通知 | ✅ 可用 | GitHub Actions 服务器端直发 |
| 在线询价 | ✅ 可用 | `POST functions/api/inquiry`（Cloudflare Functions + D1） |
| 健康检查 | ✅ 可用 | `GET functions/api/health` |
| 智能体身份 / 托管 / 结算 | 🧪 `experimental` | 有合约原型与测试，接口未冻结 |
| 公开 SDK | 🚧 `planned` | 尚未发布 |

## 想接入？先开一个对账 issue

请在仓库使用 **集成 / 对账** 模板开 issue，说明：

1. 你的项目/团队与技术栈
2. 想接入哪一层（身份 / 托管 / 结算 / 声誉 / 仅文档对账）
3. 期望的对接形态（HTTP API / SDK / 合约调用 / 纯对账）

## 设计对齐：我们希望你带来的

- **x402 式微支付**：若你的 Agent 支持 HTTP 402，结算层天然可对齐。
- **A2A / MCP**：Agent 间协作与工具暴露的事实标准，我们乐于做适配器。
- **状态机思维**：把一次协作看成「可恢复的状态图」，而非一次性调用——这是接入 ORIGIN 的心智模型。

## 我们对你的承诺

- **不吹**：文档里标 `experimental` 的接口，我们不会声称它已生产可用。
- **不锁**：协议层以开放标准为先，不强制你更换现有链或框架。
- **不募资**：本项目当前不接受代币募资；集成不需要你购买任何代币。

## 边界

- 支付/托管涉及**不可逆的资金操作**，集成前请在测试网充分验证。
- 任何涉及密钥、私钥、助记词的操作，**永远不要**写进 issue、PR 或提交历史。
