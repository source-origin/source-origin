6. 附注 · 这次提交为什么不是一次普通 push

本机的工作树与公开仓库没有共同祖先：本地是把依赖 vendored 进去的完整工程（529 文件）， 公开仓库是精选树（80 文件，offchain/ 对应 demo/，无 lib/）。 两边 ahead 20 / behind 62。直接 git push 或 --force 会删掉公开侧的 62 个提交和 SECURITY.md，所以这次改动是用 git tree API 重放文件内容上去的： 11 个路径，6 个新增 + 5 个替换，零删除，远端 tip 一变就拒跑。

写这段不是为了解释复杂，是为了让后来的人能复核：281568b 的父提交是 61a04bb， 32b8d0d 的父提交是 281568b。公开树从 80 个文件变成 86 个， 我没有动的 75 个文件逐字节保持原样。历史没有被动过。
